## 2. 仓库与数据管道结论

STEMNIST 单个样本包含 240 帧、每帧为 `16×16` 压力阵列，采样率 120 Hz，总时长 2 秒。当前 `mycode` 数据集包含 7,700 个样本和 35 个类别，标签顺序为 `A-Z` 与 `1-9`。

主要模块如下：

- `data_utils_slow.py`：启动时将 7,700 个 HDF5 样本预加载为内存张量；
- `data_utils_fast.py`：将原始 HDF5 打包成连续 Tensor 缓存，并保存 manifest 和固定数据划分；
- `model.py`：包含参数量为 6,379 的单通道 Conv-SNN；
- `function_utils.py`：包含训练、验证、最佳 checkpoint 保存和 history 可视化；
- `run.ipynb`：实验参数、数据加载、模型构造与训练入口。

## 3. 关于时间步的结论

令 `T=240`，即一帧原始压力对应一个 SNN 时间步，是合理的高时间分辨率基线：每步约对应 8.33 ms，可完整保留 120 Hz 的压力时序。

但原始帧数并不要求必须等于 SNN 时间步数。原论文的 SNN 使用经过差分阈值编码的双通道 ON/OFF 事件，并将 2 秒事件流分为 20 个时间步，每步对应 100 ms。因此：

- `T=240` 适合完整时序基线和后续硬件编码公平对照；
- `T=20/40/120` 适合时间分辨率消融和计算效率比较；
- 连续压力降采样时应在时间箱内取均值；
- 事件序列降采样时应在时间箱内统计事件数；
- 改变 `T` 时需要同时考虑 LIF 膜时间常数在物理时间上的变化。

## 4. 训练塌缩问题及诊断

初始训练曾长期出现：

```text
loss ≈ 3.5553
accuracy ≈ 0.0286
```

因为：

```text
ln(35) = 3.55535
1 / 35 = 0.02857
```

这说明 35 个类别输出基本相同，模型处于均匀随机猜测状态。结合网络输出形式，最可能的直接表现是输出 LIF 全部不放电，所有类别 logits 都为 0，`argmax` 固定选择第 0 类。

主要诱因包括：

1. 原始 ADC 压力约位于 `[75, 255]`，存在明显直流背景，直接输入阈值约为 1 的 LIF 网络会造成不合适的发放状态；
2. 原实现对 240 步输出脉冲直接求和，logits 和梯度尺度随时间步数增大；
3. 学习率 `0.005` 对当前“240 步密集原始压力”输入偏大；
4. 输出 LIF 一旦远离阈值进入沉默状态，代理梯度可能过小，模型难以自行恢复。

## 5. 当前代码中的主要修正

### 5.1 固定 ADC 量程映射

训练和验证阶段统一使用：

```python
ADC_BASELINE = 75.0
ADC_SPAN = 255.0 - ADC_BASELINE

inputs = ((inputs - ADC_BASELINE) / ADC_SPAN).clamp(0.0, 1.0)
```

该处理属于固定量程变换，不依赖验证集或测试集统计量，不产生数据泄漏。

### 5.2 使用发放率 logits

模型输出由 240 步脉冲总数改为带固定尺度的平均发放率：

```python
spike_rates = output_spikes.float().mean(dim=0)
logits = spike_rates * 10.0
```

这使输出尺度基本不再依赖 `T`，同时保留按输出发放率分类的含义。`logit_scale` 不是可训练参数，因此模型参数量仍为 6,379。

### 5.3 优化器与梯度控制

当前基线学习率由 `0.005` 降为 `0.001`，并在反向传播后加入：

```python
torch.nn.utils.clip_grad_norm_(
    model.parameters(),
    max_norm=1.0,
    error_if_nonfinite=True,
)
```

真实小批次检查中，修改后的模型能够产生非零输出发放率，所有参数梯度均为有限值。

### 5.4 发放率监控

验证阶段统计：

- `lif1` 平均发放率；
- `lif2` 平均发放率；
- `output_lif` 平均发放率。

当 `output_lif <= 1e-6` 时主动终止训练，用于及时发现网络再次进入全沉默状态。

## 8. 学习率调度器

训练函数当前采用按类型分支的 epoch 级调度逻辑：

```python
if scheduler is not None:
    if isinstance(
        scheduler,
        torch.optim.lr_scheduler.ReduceLROnPlateau,
    ):
        scheduler.step(val_loss)
    else:
        scheduler.step()
```

该逻辑兼容：

- `ReduceLROnPlateau`：根据验证损失调整；
- `CosineAnnealingLR`：每个 epoch 无参数调用；
- `StepLR`、`MultiStepLR`、`ExponentialLR` 等 epoch 级调度器。

`OneCycleLR` 和 `CyclicLR` 需要按 batch 调用，不属于当前兼容范围。

当前 history 已增加 `learning_rate` 字段，记录每个 epoch 实际使用的学习率。

建议的两种配置如下。

Plateau：

```python
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(
    optimizer,
    mode="min",
    factor=0.5,
    patience=5,
    threshold=1e-3,
    min_lr=1e-5,
)
```

Cosine：

```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer,
    T_max=NUM_EPOCHS,
    eta_min=1e-5,
)
```
